Notes and decisions for the lead
1. simrun sets the mythos tuning after sim::create. The tuning is per world and never saved, and create's sim::use
   saw phase 0. So simrun calls mythos::attach + mythos::rebuild itself, the two calls use() makes at phase >= 1,
   with no rederive, so the bits stay the same. After a --saveload it sets the tuning before sim::use. The game
   client should set MythosTune before sim::create's use(). Once B1 puts phase in Balance.cpp, balance::apply does
   this.
2. test_mythos_guard.cpp (M1) compares version-1 bytes that include the chronicle, and it calls mythos::yearly by hand
   on top of Sim's schedule, so it now runs a second yearly pass. It passes in the current tree. A diagnosis run
   showed its sim view is identical with or without the extra pass. Its narration-inclusive comparison will break
   whenever M8's mythos lines tell a passive god's world. M1b should compare the narration-free view (as in
   test_mythos_integration.cpp) and drop the manual yearly.
3. Famine deaths in the targets are Mythos's own famine-and-plague count (Faith data m_fpDead). "People lost to
   natural events" (3.1) is proxied by natural disaster events. No exact counters exist.
4. Not built (later tracks): v2 / v3 policies and the reseed (M9b / M9c). The 3.13 rite comparison (kind with
   Kindness against kind with Prayer) has no v1 policy in 5.3.
5. Build output left behind: Tools/simrun/build-m9*, SimTests/build/*-m9 (safe to delete). The private copy of
   SimTests/run.ps1 was removed.
6. A 0-byte file "Sim.cpp" at the project root (dated 2026-11-20 12:07, from the interrupted first attempt) is not
