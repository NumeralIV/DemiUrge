SUMMARY
The target is not met: 60+ fps in every view with no frame over 50 ms at 1080p High. No run, by the builder or by me, came
near it. The builder's diagnosis holds up: the near-ground hitches come from render tasks and game-thread waits that don't
get a core while the game's own long jobs fill the workers. The worker split (7 foreground + 15 background) probably helps
under heavy load, but "4.6x fewer frames over 50 ms" does not reproduce reliably: 3 of my 4 back-to-back pairs favour the
split, and 1 reverses it. But the track shipped a crash. The worker restart ran at EndOfEngineInit, while the first map was
already rendering, and one packaged launch in seven died at startup with EXCEPTION_INT_DIVIDE_BY_ZERO in the renderer
(fixed here, below). The builder's report also left out its own final editor run A3 (22 / 51 / 56 fps), which was worse
than the A1 / A2 runs it reported.

MACHINE
i7-13700K (8 P + 8 E cores, 24 threads), RTX 3060. During every run: CPU 97-100 % (2-4 other Unreal / Demiurge processes,
bursts of 25 cl.exe compiles), so every fps below is a lower bound and A/B pairs are noisy. Load samples for each run are in
docs/handoff/perf4-verify/runs-summary.txt. A quiet machine never came up during this check.

FOUND AND FIXED (Game/Core/DmTaskTuning.cpp, in main)
1. CRASH at startup (critical). Packaged run vL1 (builder's package, core split, -pyear=2000) crashed at frame 0: "Unhandled
   Exception: EXCEPTION_INT_DIVIDE_BY_ZERO, Demiurge.exe!FGatherShadowPrimitivesPrepareTask::DoTask()" on Background Worker
   #7. The DmTasks line was never logged, so it died during the restart.
   Cause: FScheduler::RestartWorkers stops every worker and then starts new ones. For a moment the scheduler has 0 workers,
   and the renderer computes FMath::DivideAndRoundUp(NumPackets, Min(GetNumWorkerThreads(), NumPackets))
   (Engine ShadowSetup.cpp:5167-5168). The track did this at EndOfEngineInit, which runs after GEngine->Start(): the first
   map's BeginPlay (the scenario's world, towns, nature, sky) has already run and the render thread is drawing it.
   Fix: restart at FCoreDelegates::OnPostEngineInit, before GEngine->Start() loads the first map, with EndOfEngineInit kept as
   a fallback. Call FlushRenderingCommands() first, so the render thread is idle while the game thread sits blocked in
   RestartWorkers. Skip it in commandlets (the cook loads the module too).
2. Startup stall. At EndOfEngineInit, RestartWorkers had to join the long jobs the scene parts had already queued. Builder's
   logs: "restarted in" 478, 1,860, 2,093, 2,385, 3,770 ms. After the fix, the new package logs "restarted in 10.3-14.4 ms
   (post engine init, before the first map)" in all 4 core-split launches (vC1, vC2, vN1, vC3), and the lane logs 34.5 ms.
   No crash in those 4 packaged launches or in the editor bridgecheck. That is too few launches to prove the race is gone,
   but the window it needs (a scene rendering during the restart) no longer exists.
3. The header comment called the target CPU "12-core / 24-thread"; corrected to 16 cores / 24 threads (8 P + 8 E).

BUILDER'S CLAIMS CHECKED
- Root cause (long jobs fill the workers; render tasks starve; frame-end wait): consistent with every log here. The new
  "frame-end wait" / "render thread" causes dominate the core-split runs; "game thread busy" dominates the engine-split runs.
- 4.6x fewer frames over 50 ms: NOT reliably reproduced (above). Same direction in 4 of 5 pairs, reversed in 1.
- Picker rebuild: correct. The per-grid cache key (geo pointer + n) is safe because Geo::build(L) is deterministic. No
  "slow dirty flush" line in 13 runs; bridgecheck pick checks pass. Speed-up still not traced.
- Frame monitor sync / frame-end wait: correct for both handler orders (MarkDrawn takes the max).
- I3 (perf-play reaches the ending): confirmed. vM1 from year 2000 reached "DmFlow: play -> ending" during the close stop
  and measured the ending screen (docs/handoff/perf4-verify/ue-perf-verify-close-ending.png). -pyear=1600 runs end around
  year 2860.
- T2 (towns exit hang): confirmed and frequent. "joined N planning tasks in" 6,981 / 16,733 / 23,238 / 38,977 / 47,172 /
  48,371 / 64,918 / 76,372 ms.
- Omitted from the report: the builder's own run A3 (editor lane, shipped setup, 23:00): 22 / 51 / 56 fps, 65 and 73
  frames over 50 ms at low / close (scratchpad perf4/w5/A3.log).
