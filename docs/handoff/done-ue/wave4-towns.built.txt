  The ground job and late probes go to a cleanup task.

  perf-play 1.3 s (tw4b). That is under 5 s.
- Final code, sky-check-w4z: RequestExit 03:34:19.191 -> log closed 03:34:19.949, so 0.76 s, with 3 jobs abandoned while
  running.
- The first sky-check tonight took 18 s. Towns EndPlay itself took 0 ms there. The 16.6 s gap was in engine teardown,
  between "Destroying PakPlatformFile" and "~FD3D12DynamicRHI", on the loaded machine.
- ENGINE ASSERT AT EXIT (not towns; for Core / bridge): "Assertion failed: Work->GetRefCount() == 0
  [QueuedThreadPoolWrapper.cpp:167]". GThreadPool is torn down while work is still queued, then the crash handler takes
  ~40 s. It happened in 4 of my 10 runs (perf-play tw4a, tw4t, tw4f; towns-look w4f). It also happens in lanes whose towns
  code still joins every task: camera4b-verify shot-cam-limb (after "joined 8 planning tasks in 43099 ms"), perf4,
  audio4b-verify, planet4-verify and towns3. Every case also has "DmSky: EndPlay left a weather build running" or the
  planet's patch jobs, both of which use Async(EAsyncExecution::ThreadPool).
  I tried a bounded 2 s wait in towns EndPlay for the cancelled jobs. It did not stop the assert (towns-look-w4f still
  crashed) and it cost 2 s, so I removed it. The comment in JoinAll records this.
  Proposed fix (owner: Core / bridge, with sky and planet): keep a handle to every GThreadPool job and retract or wait for
  it in the owning actor's EndPlay. Or move those jobs to UE::Tasks, which shut down cleanly with work still queued.

Fixes in this track:
- (new) Buildings of small settlements are hidden by tier: 10 / 18 / 28 / 45 / 70 km for camp, village, town, city,
  metropolis (5 % hysteresis; -townhidetier=<scale>, 0 = off). A village's 6-10 m houses are under one pixel beyond about
  18 km. Fields and streets stay drawn out to HideKm (70 km), so the ground does not pop. Hidden components are frozen (no
  transform updates). perf-play low view: from 1,427 components with 323 drawn down to 4-5 visible settlements. Render
  thread fell 38.5 -> 28.2 ms (low) and 36.1 -> 26.2 ms (close), on a machine whose load differed between runs.
- (new, perf4 T3) Unit components have a fixed capacity that only grows, in powers of two (minimum 8). Spare slots are
  hidden (scale 0). Components with no units are skipped. No more ClearInstances + AddInstances render-state rebuilds when
  a unit appears or leaves. Unit components now update instance deltas only (MarkRenderTransformDirty, no proxy rebuild).
- (first run) Applies are budgeted (2 ms), launches are capped, and the construction diff runs on the worker.
- Still over budget: about 8 ms of extra render-thread time with 300-500 drawn components in live play. Next step, in
  order: merge each settlement's batches per cell into fewer components, and test whether the 263 Nanite ISM components
  get cheaper if their transform is not touched every frame (one planet-fixed parent). An Unreal Insights trace of the
  low view would decide this; the machine was too loaded tonight.

======================================================================== 4. REAL BLENDER ASSETS
- Import: Unreal/Scripts/assets/import_assets.ps1 into the lane (first run, 2026-11-20): DMI RESULT PASS, 0 plan issues.
  It imported age0-age6, ship, unit, wonder and shrine (534 meshes planned, 286 material instances, 224 textures). The
  importer's game LOD profile was used. Building-class meshes are Nanite: the towns log says "real assets: 114 of 114
  mapped assets loaded (295 meshes with their states, 263 Nanite, 3720 slot variants), 742 table entries". The one
  importer change makes M_DmKit compile for Nanite (HLSL 2021 rejects a vector ternary; it uses select() now).
- Factory (DmTownsAssets.h/.cpp, DmTownsKit, DmTownsPlan, DmTownsActor):
  - The ASSET-INTEGRATION 4.1 table maps kit id x variant x age (and tier for the Atomic height classes Low / Mid / High)
    to assets. Several assets for one entry are alternatives, picked per building by hash (FDmTownInst::Sub).
  - The planner places each building with the real asset's footprint per age (FDmKitTable::GetAt).
  - States: a new building shows the asset's own _Construction mesh. A dead town shows each asset's own _Ruin on the same
    footprint.
  - Culture style is computed per culture from its capital (ASSET-INTEGRATION 4.2): Valley, Cliff-Terrace,
    Lagoon-Weaver or Ring-Builder. Daughter cultures inherit their parent's style.
  - Climate instances (Age0, wonders-a) and culture-style instances are component material overrides. Per-instance tint,
    window light and state stay in custom data. MPC_DmAssets gets the planet frame, night override and glow.
  - LODs: Nanite for buildings, so the plain ISMs keep custom data and get per-cluster detail.
  - Units and ships use the real meshes by type and age.
  - Pool warming registers one component per asset mesh at world load, so no mesh is registered for the first time
    mid-game.
  - The generated stand-ins remain for every gap: piers, Villa, MarketHall, TempleLate, Windmill and the others in 4.9.
    -townassets=0 turns the assets off for A/B.
- Load cost: the assets load synchronously once at world load: 4.3 s on a warm DDC, 87 s on a cold one under load.
  Editor only: the first launch after the import, or after a DDC invalidation (it happened again after tonight's refresh),
  builds the distance fields and Lumen cards of every asset mesh on the game thread before frame 1. That was 40-50 min on
  this loaded machine. Cooked builds do not pay it.
  Suggestion: drop DF generation for the _Construction / _Ruin states in the importer, or warm only the age in play.
- Not done: the culture overlay meshes (art/culture: A/B/C roofs, stilts, drum houses), socket-driven smoke and crowns,
  and FDmTownInput::Damage -> _Damaged.

======================================================================== 5. GROUND NEAR TOWNS
- Fields (first run, DmTownsPlan PlanFields): organic parcels after docs/lab/ground.md 5.1-5.2.
  - Holdings are warped Voronoi cells. Each takes its direction from the contours on slopes, or from a smooth regional
    grain otherwise.
  - Holdings are cut into furlongs (long strips whose ends line up) or irregular polygons.
  - Each field is tilled or left fallow on its own, so farmland frays into meadow. Hedges and tracks run between holdings.
  - Crop colours depend on climate. Each parcel polygon is cut by an ~18 m grid in its own frame, so it drapes over the
    terrain.
- (new) The plaza is now rings of ~7 m that drape over the slope. Before, it was one flat fan of 10-40 triangles. It also
  has a ragged worn edge, darker paving with per-vertex tone, and half the old lamp emission, so it no longer glows white
  at night.
- Still a patchwork at 2 km: the large straight-edged rectangles beyond the town are the PLANET's farmland paint (they
  show with -townfields=0 too: shots/ue-towns-town-nofields-fields-day.png). That belongs to the planet owner and the
  ground.md land-use layer.
