FIXES (all in the lane, all in towns-owned files; marked "(verifier)" / "(verifier fix)" in the code)
1. Rivers were never seen by any town (pre-existing since an earlier verifier fix, made visible by this check): DmTownsGround.cpp
   RiverSegments read TSet::Add's out flag ("already in the set") as "new", so it skipped every reach. Evidence: new plan-note
   diagnostics showed "rivers 0 (0 nodes)" on all 58 plans while RiverQuery put settlement 59's centre 51 m from a bank; houses and
   ruins stood in the river (shots/ue-towns-ruins-v4fix.png, ue-towns-town-v4-300-day.png top). After: 43 of 70 plans see rivers
   (plan 59: 729 reaches, 2,065 grid nodes blocked, 179 -> 164 houses, the wall stops at the river), channel clear
   (shots/ue-towns-ruins-v4b.png, ue-towns-town-v4b-300-day.png, -2km-day.png).
2. Wrong materials on _Construction / _Ruin meshes: the culture/climate overrides were built from the _Intact mesh's slot list and
   applied by index to every state. 43 of the 132 imported assets have state meshes with fewer or reordered slots (plan.json:
   e.g. Age3_Townhouse_A_Construction = Structure, Detail vs Intact Structure, Roof, Detail), so roof tiles went onto the Detail slot
   of every Sail-age construction site and ruin. Now per state from that mesh's own slots (DmTownsAssets.h/.cpp: Mats[state][style]
   [climate]; DmTownsActor.cpp ResolveLook uses the state actually drawn). Slot variants 3,720 -> 9,528. Not shown as a visual A/B:
   the builder-lane ruins run drew no town within its 240 frames (planet terrain still pending), see shots/ue-towns-ruins-v4builder.png.
3. Longest planning slice (brief item 2, the builder's open point): raster and field overlay are now sliced too (DmTownsPlan.cpp:
   BuildRasterRows in bands of 8 rows, BuildOverlayFields in groups of 4 parcels, both resumable and cancel-checked; the rest of the
   overlay unchanged and in the same order, plan 59 output identical: 305 instances, 21,311 overlay tris). Longest slice CPU:
   builder 303-447 ms -> 15-60 ms in my runs (sky-check 15.3, towns-look 23.6 / 26.0, perf-play 41-84 on the loaded machine).
4. Plaza at night: the builder's drape rings set uv0.y = 1 on every ring, but M_TownGround (Scripts/towns.py) reads uv0.y as
   0 centre .. 1 rim to put the lamps on the rim, so the whole disc glowed with a dark spot over the centre fan
   (shots/ue-towns-town-v4-40-night.png). Ring vertices now carry the ring fraction (ue-towns-town-v4b-300-night.png: no spot).
Plus diagnostics: plan notes print "rivers N (nodes, bank m)", the ground line prints river points / grid cells.
